네트워크 기초 + Amazon VPC 주차. 네트워크 도구로 경로·IP를 확인하고, VPC에 퍼블릭/프라이빗 서브넷을 구성한 뒤 통신을 확인하고 삭제하는 순서로 실습한다.

## 개념 요약

- **VPC (Virtual Private Cloud)** — 사용자 정의 가상 프라이빗 클라우드 네트워크. 리전마다 독립적으로 구성된다.
- **서브넷** — VPC 내부를 나눈 네트워크. 반드시 하나의 가용 영역에 종속된다. **VPC라는 큰 CIDR에서 서브넷이라는 작은 CIDR을 분할**한다.
- **IGW(인터넷 게이트웨이)** — 라우팅 타깃을 IGW로 지정하면 **퍼블릭 서브넷**이 된다.
- **NAT 게이트웨이** — **프라이빗 서브넷**에서 외부로 나갈 때 쓰는 관문. 외부에서 프라이빗 IP로 들어오는 통신은 불가능하다.
- 보안 그룹(스테이트풀, 자원 단위) vs 네트워크 ACL(스테이트리스, 서브넷 단위).

## 실습 ① 네트워크 도구로 확인하기

1. **Cisco Packet Tracer** 로 NAT 네트워크 구성, 퍼블릭/프라이빗 IP·서브넷 마스크 적용
2. **Wireshark** 로 패킷 캡처·분석
3. 리눅스 **traceroute** 로 목적지까지 거치는 경로(홉) 확인
4. **KISA 후이즈**(whois.kisa.or.kr)에서 IP 정보 조회

```bash
traceroute <대상>        # 목적지까지의 네트워크 경로(홉) 확인
```

## 실습 ② VPC로 퍼블릭/프라이빗 서브넷 구성하기

### 단계 ① VPC 생성

1. VPC 콘솔 → **[VPC 생성]**
2. 이름과 **IP CIDR**(예: `10.0.0.0/16`) 지정

!!! capture "VPC 생성 화면"
    (실습 화면 캡처)

### 단계 ② 퍼블릭 서브넷 생성

1. VPC의 CIDR에서 분할한 **서브넷**(예: `10.0.1.0/24`)을 특정 가용 영역에 생성
2. **인터넷 게이트웨이(IGW)** 생성 후 VPC에 연결
3. 서브넷 **라우팅 테이블**에 `0.0.0.0/0 → IGW` 경로 추가

!!! capture "서브넷·라우팅 테이블 / IGW 연결"
    (실습 화면 캡처)

### 단계 ③ 퍼블릭 서브넷 통신 확인

퍼블릭 서브넷에 인스턴스를 두고 퍼블릭 IP를 할당한 뒤, 외부 인터넷과 통신되는지 확인한다.

!!! note "퍼블릭 서브넷 통신 — 외부 공개 3조건"
    퍼블릭 서브넷 배치 + 퍼블릭 IP 부여 + 보안 그룹 허용의 세 조건이 모두 충족되면 외부에서 인스턴스에 접속된다. 이 동작 자체는 2주차에서 EC2에 퍼블릭 IP로 웹 접속을 확인한 것과 동일한 원리다.

### 단계 ④ 프라이빗 서브넷 생성

1. 다른 CIDR(예: `10.0.2.0/24`)로 **프라이빗 서브넷** 생성
2. 외부로 나가는 통신이 필요하면 **NAT 게이트웨이**를 두고 라우팅 타깃으로 지정

### 단계 ⑤ 프라이빗 서브넷 통신 확인

프라이빗 서브넷의 인스턴스가 NAT 게이트웨이를 거쳐 외부로 나가는지, 외부에서는 직접 접근되지 않는지 확인한다.

!!! note "프라이빗 서브넷 통신 — NAT 게이트웨이는 미생성"
    프라이빗 서브넷 인스턴스는 NAT 게이트웨이를 거쳐야만 외부로 나가고, 외부에서 프라이빗 IP로 직접 들어오지는 못한다. NAT 게이트웨이는 실행 시간당·데이터 처리량당 과금되므로 본 실습에서는 구성 원리만 확인하고 실제 생성은 하지 않았다(불필요한 과금 방지).

### 단계 ⑥ 자원 전체 삭제

NAT 게이트웨이·IGW·서브넷·VPC 등 생성한 자원을 모두 삭제한다.

!!! warning "NAT 게이트웨이는 과금된다"
    NAT 게이트웨이는 실행 중 시간당 요금과 데이터 처리 요금이 발생한다. 실습 후 NAT 게이트웨이부터 삭제한다.

## 막혔던 점

- VPC 피어링 연결 실패 → 두 VPC의 IP CIDR이 중복되면 불가. 비중복으로 재설계 후 피어링.
- 퍼블릭 서브넷인데 인터넷이 안 됨 → 라우팅 테이블에 `0.0.0.0/0 → IGW` 추가 + 퍼블릭 IP 할당.
- 프라이빗 서브넷에서 외부로 못 나감 → NAT 게이트웨이 생성 후 라우팅 타깃으로 지정.
- 보안 그룹을 열었는데 트래픽 차단 → NACL은 스테이트리스이므로 회신용 임시 포트(동적 포트 범위)를 인바운드·아웃바운드 양방향 허용.
- ping이 안 됨 → ping은 ICMP를 쓰므로 보안 규칙에 ICMP 허용 추가.
